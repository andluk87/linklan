# Сборки и выпуски на GitHub

Этот проект восстановлен из исходников 0.2.1. Готовый клиент 0.2.2 не содержит
исходников, поэтому его дополнительные изменения интерфейса сюда не перенесены.
Версия 0.2.4 добавляет CI, проверку согласованности релиза и режим API без сайта.

`release-version` задаёт версию автоматической сборки. Push в `main` и ручной
запуск **Actions → Test and build LinkLAN → Run workflow** запускают тесты с
PostgreSQL, go vet, сборку Windows x64 и NSIS-установщика. Результаты доступны
в artifact `LinkLAN-vX.Y.Z`. Внутри: `LinkLAN-Windows-x64-vX.Y.Z.zip`,
`LinkLAN-Setup-x64-vX.Y.Z.exe`, исходники, update ZIP, manifest и SHA256SUMS.
При неудаче тестов сборка не запускается.

Для выпуска измените `release-version`, тексты документации и версию по умолчанию
в `internal/model/model.go`, закоммитьте изменения и отправьте tag:

```bash
git tag v0.2.4
git push origin main v0.2.4
```

Tag должен совпадать с `release-version`. Windows runner дополнительно проверяет тихую установку, команду удаления в реестре,
самопроверку установленного EXE и его версию. После успешных тестов и сборки workflow
создаёт GitHub Release и прикладывает файлы. GitHub Actions должны быть включены
для репозитория. Ключ подписи обновлений по умолчанию не задаётся; эти сборки
предназначены для ручной установки и не имеют Authenticode-подписи издателя.
Повторную публикацию того же tag не используют: для нового релиза повышают версию.

Локальная сборка без Docker (Go 1.26.8, Python 3, NSIS для установщика):

```bash
python3 scripts/build-client.py --installer
python3 scripts/publish-downloads.py
python3 scripts/package-update.py
```

Wintun скачивается с официального сайта и проверяется по закреплённому SHA-256.
`--wintun-archive /path/wintun-0.14.1.zip` позволяет использовать кеш оригинального
архива с той же обязательной проверкой. Старые EXE из входных архивов не
используются как результат новой сборки. Бинарники хранятся в Releases, не в Git.

## API по HTTPS на 8191 без сайта

Режим из патча `api-8191-fix` доступен через `compose.api.yml`. Он не зависит от
Caddy и не копирует сертификаты из чужих контейнеров. Подготовьте действующие
`deploy/certs/server.crt` (full chain) и `deploy/certs/server.key` для своего домена,
а также `.env` с внешними адресами relay/STUN. Сертификаты и ключи не включаются
в Git или исходный ZIP. Продление сертификата настраивается отдельно на сервере.

```bash
# При переходе со стека с сайтом остановите только его web-контейнер.
docker compose stop web
docker compose -f compose.yml -f compose.api.yml up -d --build
curl --fail https://YOUR_DOMAIN:8191/api/health
```

В клиенте укажите `YOUR_DOMAIN:8191`. `/`, `/admin` и `/downloads/` возвращают 404;
`/api/metrics` закрыт, `/api/` и WebSocket проксируются к API. В этой схеме
клиенты обновляются вручную. Обычный режим с сайтом остаётся в `compose.yml`.
Не включайте профиль `website` одновременно с API gateway: оба занимают 8191.

Патч миграции DPAPI-профиля из присланного архива рассчитан на конкретный домен
и существующее устройство. Он не запускается при сборке или настройке среды.
