# LinkLAN 0.5.0: клиент и администрирование

Сервер 0.2.5 продолжит обслуживать VPN-клиент. Для новой админ-панели требуется сервер 0.5.0.

На вашем сервере `/root/LinkLAN`:

```sh
curl -fsSL https://raw.githubusercontent.com/andluk87/linklan/v0.5.0/scripts/upgrade-server.sh -o /tmp/linklan-upgrade.sh
bash /tmp/linklan-upgrade.sh
```

Скрипт сохраняет БД и проект в отдельный каталог, проверяет SHA256 архива, сохраняет существующие `.env`, Compose-файлы и сертификаты. Собирается и перезапускается только `api`; PostgreSQL, Redis, relay, gateway и соседние проекты не пересоздаются. Административная настройка добавляется отдельным `compose.admin.yml`. При последующих ручных обновлениях включайте его последним:

```sh
docker compose -f compose.yml -f compose.api-8191.yml -f compose.admin.yml up -d --no-deps --build api
```

Панель: **Система → Админ-панель сервера** или `https://linklan.lknet.ru:8191/api/admin`. На самом сервере посмотрите токен командой `cat /root/LinkLAN/.secrets/admin-token` и вставьте в поле входа. Не публикуйте токен и не отправляйте его в чат. В браузере он хранится только до выхода/перезагрузки вкладки; каждый API-запрос проверяет токен заново. Обычные VPN JWT и старое email/password-администрирование не дают доступа к панели.

Для нового развёртывания: `python3 scripts/init-admin-token.py`, затем добавьте `-f compose.admin.yml` к своим Compose-файлам. Скрипт не заменяет существующий токен. Корневой запуск назначает владельцем UID 65532 (пользователь контейнера API), права 0600; каталог 0700. При запуске обычным пользователем файл 0444 внутри приватного каталога 0700.

Ротация: сохраните старый файл в закрытом месте, удалите `.secrets/admin-token`, повторите скрипт генерации и **пересоздайте API** (`up -d --no-deps --force-recreate api` с теми же Compose-файлами). Старый токен перестанет работать. Бинарный сервер принимает также `ADMIN_TOKEN`, но для Docker предпочтителен `ADMIN_TOKEN_FILE` с read-only bind mount.

Панель создаёт пользователей и сети для существующего устройства, управляет данными LinkLAN: пользователями, ролями, блокировками, сетями, владельцами, режимами доступа, паролями, лимитами, приглашениями, устройствами, активными подключениями, заявками и участниками. Есть режим обслуживания, запрет регистрации аккаунтов, поиск по текущей странице, пагинация, экспорт текущей выборки и аудит. Страница содержит до 200 объектов каждого типа и 100 событий; кнопка «Далее» открывает следующие. Экспорт состояния — JSON для просмотра, **не резервная копия БД**.

Отключение завершает текущее соединение; клиент с автоподключением может подключиться снова. Для запрета используйте блокировку. Режим обслуживания запрещает новые подключения и создание/вступление в сети, сохраняя уже работающие соединения. Запрет регистрации относится к email-аккаунтам; для запрета входа устройств включайте обслуживание.

Управление ОС, SSH, Docker, TLS-сертификатами и резервными копиями выполняется на хосте. У контейнера API нет Docker socket и привилегий для перезагрузки хоста. Relay/STUN и параметры SMTP отображаются/задаются через конфигурацию развёртывания; секреты не возвращаются в API.

Удаление пользователя каскадно удаляет его устройства и принадлежащие ему сети. Удаление сети удаляет участников и приглашения. Эти действия требуют подтверждения в панели; восстановление — из резервной копии PostgreSQL.

Откат: остановите API, восстановите исходники из `project.tar.gz`, запустите прежний API с исходными Compose-файлами. Миграция 3 добавляет только таблицу настроек и совместима со старым API. Если выполнялись удаления данных, восстановите `database.sql.gz` в PostgreSQL при остановленном API; это заменяет текущее состояние БД и требует отдельного решения администратора.

Интерфейс ориентирован на приложенное видео: компактная тёмная тема, карточка ПК, сети, выбор узлов, контекстные меню, отдельный Windows ping, боковое меню настроек, светлая тема, красная кнопка выключенного соединения. Функции Radmin Remote Control, публичный каталог игр и собственный файловый протокол не реализуются фиктивными пунктами: доступны стандартные Windows RDP и общие папки SMB. Проверка реального VPN, Windows-входа и нескольких физических мониторов выполняется на Windows.
