# Обновление LinkLAN до 0.2.1

В этом выпуске изменён Windows-клиент: компактное окно, свой компьютер только
в верхней панели, ICMP-индикаторы других участников и запрос брандмауэра.
Клиент совместим с уже работающим сервером 0.2.0.

## Обновление клиента

1. Закройте LinkLAN и распакуйте `LinkLAN-Windows-x64-v0.2.1.zip` целиком
   вместо прежних файлов, включая `wintun.dll`.
2. Сохраните `%APPDATA%\LinkLAN\profile.dpapi` и используйте того же
   Windows-пользователя: в профиле находятся ключ устройства и ваши сети.
3. Запустите `LinkLAN.exe`. Разрешите UAC и нажмите «Да» в запросе
   «LinkLAN — брандмауэр». После успешной настройки согласие запоминается.
4. Домен остаётся `linklan.lknet.ru`. Включите нужную сеть кнопкой ON/OFF.

При отказе настройку можно повторить в меню
«Система → Доступ через брандмауэр…». Правила разрешают трафик LinkLAN.exe
и все протоколы своего виртуального адаптера, локального IP и подсети.
При отключении сети правила адаптера удаляются.

## Обновление лендинга на вашем сервере

Чтобы новые файлы скачивались с `https://linklan.lknet.ru`, скопируйте
`LinkLAN-update-v0.2.1.zip` в `/root/LinkLAN` и выполните:

~~~bash
cd /root/LinkLAN
unzip -o LinkLAN-update-v0.2.1.zip -d .
cp LinkLAN-update-v0.2.1.zip web/downloads/
docker compose -f compose.yml -f compose.caddy.yml up -d web
~~~

Для обновления страницы и ZIP достаточно контейнера web: API/relay 0.2.0
совместимы. Архив также содержит исходники 0.2.1; если хотите пересобрать API,
выполните `docker compose -f compose.yml -f compose.caddy.yml up -d --build api web`.
После пересборки `/api/health` сообщает версию 0.2.1.

Архив сохраняет `.env`, корневые `compose*.yml` и существующие тома базы.
Веб остаётся на 8191, а внешний Caddy — на 443 с сетью `volna_default` и
адресом `linklan-web:80`. Менять Caddy и UDP-порты не требуется.

Все vendored Go-файлы включены, в том числе
`vendor/golang.org/x/text/internal/language/compose.go`. Проверка упаковки
сравнивает полный набор исходников и содержимое файлов перед выпуском ZIP.
